# 问题

- 开机先看15秒广告，进桌面点一下要等1\~2秒，切应用黑屏几秒，越用越卡。
- 经常出现视频App播放一段时间就会秒退。
- 原因: 设备只有1.45GB内存，系统桌面+画报+远场语音把内存吃光（详见下表），Swap用了202MB在硬撑。
- 要求：不root、不刷机，改动 **随时能还原** ；万一哪天连不上，家人用遥控器也能自己恢复。

| 网络 | 投影 192.168.31.167:5555，网关 192.168.31.1 |
| 工具 | 官方 platform-tools（adb），无 root、无 su |

# 思路

停推送/广告、换桌面、装 APK、抓日志定位卡顿、关动画。投影本质就是一台 Android 设备, 通过三类 **可逆** adb 操作：

- `pm disable-user --user 0 <包>` ：停用预装应用（ `pm enable` 还原，不卸载）；
- `settings put global ...` ：关动画等参数；
- `cmd package set-home-activity` ：换默认桌面。

# 直接让WorkBuddy搞定

注: 只读优先、逐项确认、留回退、不擅自重启

> 我要优化一台Redmi投影，主要是卡顿和开机广告。电脑是 Windows + Git Bash， 和设备在同一局域网。按这个规矩来，不要自作主张：
>
> 1.  先确认电脑有没有 adb，没有就下载官方 platform-tools 到当前目录（不改系统 PATH），并写一个只读体检脚本：只采集型号、系统版本、内存、CPU、已装应用、分辨率、默认桌面，一个设置都不许改。
> 2.  告诉我设备端要开什么开关、怎么找 IP；等我确认开好了再连。
> 3.  连上后先出只读报告，指出卡顿来源和广告承载组件，再给分档优化清单：每档写清收益、副作用、风险，等我逐项确认才动手。
> 4.  所有改动一律用可还原的 pm disable-user / settings put，日志里留逐条回退命令；禁止卸载系统应用、禁止刷机、禁止改画质参数。
> 5.  换桌面去广告必须按「安装 → 确认注册 HOME → 启动验前台 → 截图确认不黑屏 → 设为默认→ 按 HOME 验证 → 最后才停用系统桌面」的顺序，不许跳步。
> 6.  不要主动断电重启（国行固件重启会关掉网络 ADB）。
> 7.  每步命令、结果、截图落文件；最后给我一键还原脚本和可复现笔记。
>

# WorkBuddy内部操作流程

## 只读体检

`bash 02-tv-doctor.sh auto` → 产出 \~17 KB 报告。关键结论：

| 指标 | 体检值 | 判断 |
|----|----|----|
| 可用内存 / 真空闲 | 321 MB / 50 MB | 被榨干 |
| Swap 已用 | 202 MB | 直接卡顿源 |
| load average | 5.70（4 核） | 过载 |
| `com.asu.asuaispeech` | 38% CPU | 远场语音常驻，最大 CPU 户 |
| `com.mitv.tvhome.pub` | 196 MB | 系统桌面，也是广告载体 |
| `com.xiaomi.tv.common.gallery` | 271 MB + 34% CPU | 小米画报持续下图，比桌面还重 |
| 独立广告 APK | 不存在 | 广告跟着系统桌面走 → 换桌面即去广告 |

## 分档停用

`03-optimize.sh` 的档位： `a` （推广/统计 6 包 + 动画 0.5）→ `voice` （远场语音）→ `gallery` （小米画报）→ `webcontent` （WebView/推送容器）。

| 包 | 作用 | 代价 |
|----|----|----|
| `com.duokan.videodaily` / `shoppub` / `appstore.common` | 视频日报 / 商城 / 应用商店 | 商店装不了 App |
| `com.xiaomi.mitv.payment` / `.pay` / `com.miui.analytics` | 支付 / 统计 | 应用内购买不可用 |
| `com.asu.asuaispeech` / `com.asu.xiaoaiservice` | 远场语音 / 小爱 | 语音遥控失效，按键正常 |
| `com.xiaomi.tv.common.gallery` | 小米画报屏保 | 屏保消失 |
| `com.xm.webcontent` | WebView 容器 / 推送 | 部分内嵌网页打不开 |
| `com.mitv.tvhome.pub` | **系统桌面（广告来源）** | 需自建设置入口 |

两个实测细节：组件级停用会被固件拒绝（ `SecurityException` ），只能整包停用；停用后 `dumpsys cpuinfo` 仍显示旧高占用，那是历史窗口，看 `top -n 1` 才算即时值。

## 换桌面（顺序就是安全绳）

新桌面 tvhome-zh v1.6.1（ `com.gathin.tvhome` ，419 KB， **纯 Java 无 native 库** ，天然兼容 32 位）。执行顺序，每步有证据才进下一步：

    adb install -r  →  pm list packages -3 出现新包  →  am start 后前台就是它
    →  screencap 截图人眼确认不黑屏  →  set-home-activity 设默认  →  按 HOME 能回来
    →  最后才 pm disable-user com.mitv.tvhome.pub + com.xm.webcontent

![停用系统桌面后的最终画面：无广告、无桌面选择弹窗](https://img.19921514.xyz/notes/%E7%94%9F%E6%B4%BB/%E6%90%9E%E6%9C%BA/images/%E6%8A%95%E5%BD%B1%E4%BB%AA-12-launcher-final.png)

## 断电重启后怎么恢复

1.  桌面第一行最左蓝色齿轮 →「设置」（别点顶栏那个写着「设置」的齿轮，它永远报不支持）；
2.  设置 → 关于 → 连按「设备名称」进开发者模式；
3.  「ADB 调试」关一次再打开 → 5555 恢复；
4.  电脑 `bash 02-tv-doctor.sh auto` 重连。

备用方案：USB 双公头线连电脑 `adb tcpip 5555` 后拔线。别写 `persist.adb.tcp.port` ，adbd 根本不读它，只会给自己假安全感。

## 一键还原

`bash 99-restore-all.sh` ：重新启用 11 个包 → 默认桌面切回 `com.mitv.tvhome.pub/com.mitv.tvhome.MainActivityUserMode` → 动画恢复 1.0 → 打核验结果。可重复执行，不删数据。

# 问题处理

## 点设置提示此电视不支持: 一样的扔给workbuddy让它搞定

根因有两层：① 国行固件不响应标准 `android.settings.SETTINGS` intent（桌面程序写死了这个）；② tvhome-zh 的应用列表只查 `CATEGORY_LEANBACK_LAUNCHER` ，而系统设置只注册了普通 `LAUNCHER` ，所以桌面上永远看不到「设置」。

系统设置的真实入口是 `com.android.settings/com.asu.settings.TvMainActivity` ，但重启后要重开 ADB 又不能依赖电脑，于是用桌面自带「应用库」把「设置」做成桌面图标：

![应用库「桌面上的应用」里有「设置」行，勾选后会出现在桌面](https://img.19921514.xyz/notes/%E7%94%9F%E6%B4%BB/%E6%90%9E%E6%9C%BA/images/%E6%8A%95%E5%BD%B1%E4%BB%AA-22-library-panel.png)

![点第一行最左的蓝色齿轮，实测进入 com.asu.settings.TvMainActivity](https://img.19921514.xyz/notes/%E7%94%9F%E6%B4%BB/%E6%90%9E%E6%9C%BA/images/%E6%8A%95%E5%BD%B1%E4%BB%AA-32-settings-via-tile.png)

坑： `input tap` 对弹窗里的列表行 **只给焦点不触发点击** ，必须补 `inputkeyevent 23` （DPAD_CENTER）才真正勾选，判据是该行出现 `id/tick` 。脚本 06 已封装，1920x1080 坐标写死、可用环境变量覆盖。
